# LLM 사용량 기록·비용 계산과 사용자별 일일 예산 상한

## 목적 / 성공 조건
- 목적: #174로 LLM 호출·토큰을 지표로 볼 수 있게 됐지만, 지표는 메모리에 있어 재기동하면 사라지고, 누가 얼마나 썼는지·얼마가 들었는지는 알 수 없으며, 한 사용자가 LLM을 무제한으로 부를 수 있다. LLM 호출마다 사용자·기능·토큰·비용을 DB에 남기고, 사용자별 일일 비용 상한을 넘으면 모델을 부르지 않게 한다. 계산 비용이 실제 청구와 맞는지도 대조한다.
- 기술적 완료:
  - 가격표를 제품 코드 쪽 한 곳(`backend/src/main/resources/llm/pricing.json`, 모델별 USD/1M 토큰·확인 날짜·출처)으로 옮기고, 평가 하네스도 같은 파일을 읽는다.
  - LLM 호출마다 `llm_usages`에 한 행: 사용자, 기능(diagnosis·nlp), 공급사, 모델, 결과(success·error), 입력·캐시 입력·출력·추론 토큰, 계산 비용(USD, 가격이 없으면 null), 지연, 시각, 관련 ID(배포·명령 기록).
  - 지표: `klepaas_llm_cost_usd_total{feature, provider, model}`, 가격이 없는 모델 호출 `klepaas_llm_unpriced_calls_total{model}`, 예산 초과 `klepaas_llm_budget_exceeded_total{feature}`.
  - 사용자별 일일 비용 상한(`llm.budget.daily-usd-per-user`): 모델을 부르기 전에 오늘 사용액을 보고, 넘었으면 부르지 않는다(동작은 Q1).
  - 본인 사용량 조회 API와 CLI(Q3).
  - 계산 비용과 공급사 청구액 대조 1회(Q4).
- 운영: 상한 안에서는 지금과 같다. 상한을 넘으면 Q1 동작. 기본 상한값은 Q2.

## 범위
- 포함: 가격표 이동·통합, Flyway `V11__llm_usages.sql`, 사용량 기록·예산 검사 서비스, 진단·자연어 호출 지점 연결, 비용·예산 지표, 에러 코드(Q1), 조회 API·CLI(Q3), 대조 기록, 문서(architecture·observability·README·CLI_REFERENCE·product), 테스트.
- 제외: 로컬 모델로 낮추기(운영 서버에 GPU가 없어 운영에서 쓸 수 없다), 조직·팀 단위 예산, 월 단위 상한, 관리자 화면, 알림, 공급사 관리자 키를 쓰는 자동 청구 대조(Q4), 콘솔 화면.

## 입출력·계약
- 저장: `V11__llm_usages.sql` — `llm_usages(id bigserial, created_at timestamptz not null, user_id bigint not null, feature varchar(20), provider varchar(30), model varchar(100), outcome varchar(10), input_tokens bigint, cached_input_tokens bigint, output_tokens bigint, reasoning_tokens bigint, cost_usd numeric(12,6), latency_ms bigint, deployment_id bigint)`, 인덱스 `(user_id, created_at)`. 새 테이블이라 이전 릴리스와 호환(ADR-0004). 기존 행 없음.
- 일일 경계: `Asia/Seoul` 자정 기준(Q2와 함께 확인).
- 예산 검사: 호출 전에 `user_id`의 오늘 `cost_usd` 합이 상한 이상이면 초과. 동시 요청은 막지 않는다(검사와 기록 사이에 들어온 요청 몇 건만큼 상한을 넘을 수 있는 **느슨한 상한**). 가격이 없는 호출(로컬 모델 등)은 비용 0으로 보고 상한에 걸리지 않는다.
- API(Q3): `GET /api/v1/llm/usage?days=7` — 본인 일별·기능별 호출 수·토큰·비용과 오늘 남은 예산. READ_ONLY 이상.
- 에러(Q1): 새 `AI_007 LLM_BUDGET_EXCEEDED`(HTTP 429).
- 설정: `llm.budget.daily-usd-per-user`(`LLM_BUDGET_DAILY_USD_PER_USER`), 0이면 상한 없음.

## 권한·안전
- 사용량 조회는 본인 것만. 다른 사용자 사용량은 응답에 없다.
- 상한 검사는 모델 호출 전, 소유권·상태 검사 뒤에 한다(권한 없는 요청이 사용량에 남지 않게).
- 사용량 행에 프롬프트·응답·비밀값을 넣지 않는다.
- 기록 실패(DB 오류)는 진단·명령 결과를 막지 않는다: 경고 로그와 지표만 남긴다. 단, 그 호출은 상한 계산에서 빠질 수 있다(문서화).

## 제약
- 참조: [observability](../../observability.md), [#174](../0174-llm-usage-metrics/spec.md), [#115 비용 측정·잔액 대조](../0115-diagnosis-cost-reduction/spec.md), [ADR-0004](../../adr/0004-flyway-forward-compatible-migrations.md)
- 비용 = (input − cached_input) × 입력 가격 + cached_input × 캐시 입력 가격 + output × 출력 가격 (출력은 추론 포함). 평가 하네스와 같은 식.
- 가격은 확인 날짜와 출처를 함께 둔다. 바꿀 때는 PR로.
- 규칙·근거 없음·재사용 경로(모델 미호출)는 사용량 행을 남기지 않는다(지표 `klepaas_diagnosis_requests_total`이 있다).

### 실제 실행 (로컬: 패키징 JAR + PostgreSQL 16 + 임시 k3s, `gpt-6-luna` 실제 호출)
- 1차(상한 $0.0008): 자연어 명령 3건·진단 1건이 `llm_usages`에 기록. 같은 문장을 반복한 명령은 입력 1,290 중 1,287이 캐시 입력이라 $0.000036, 다른 문장은 $0.000188, 진단은 $0.000640(입력 2,079·출력 864, 추론 512). 조회 API가 오늘 사용액·남은 예산·일별 합계를 보였고 비용 지표가 기능별로 쌓였다. 진단을 부르기 전 사용액이 상한 미만이라 초과는 나지 않았다.
- 2차(상한 $0.0001): 명령 1건($0.000064) 뒤 두 번째 명령은 검사 시점 사용액이 상한 미만이라 통과(느슨한 상한), 그 뒤 사용액 $0.000100 → 진단은 모델 없이 `model=none`·`budget-exceeded-v1`·판단 보류, 경고 "오늘 LLM 예산(사용자당 하루 $0.0001)을 넘어 모델을 부르지 않았습니다", `klepaas_llm_budget_exceeded_total{feature=diagnosis}` 1. 자연어 429는 HTTP 테스트로 확인했다.
- 원자료 `.local/evidence/0176-llm-budget/`.

### 청구 대조 (Q4, 2026-10-24~25)
통제된 묶음: 로컬 패키징 JAR로 느린 기동 실패 배포 하나를 `refresh=true`로 300번 진단해 `gpt-6-luna`를 300번 불렀다(2026-10-24 18:14:41~18:27:01 UTC, 동시 4, 예산 상한 끔). 사용자가 묶음 전후로 OpenAI 사용량 화면 값을 확인했다.

| 항목 | 묶음 전 | 묶음 후 | 증가 (OpenAI) | DB `llm_usages` 합 (계산) |
|---|---|---|---|---|
| 요청 수 | 121 | 424 | **+303** | 300 (모두 성공) |
| 입력 토큰 | 455,262 | 1,247,373 | **+792,111** | 788,239 (캐시 입력 698,999 포함) |
| 비용 (화면, 센트 반올림) | 7일 $0.09 / KLePaas 10월 $0.91 | 주간 $0.24 / KLePaas 10월 $1.06 | **+$0.15** (두 화면 모두) | **$0.146861** |

- 비용: 계산 $0.146861은 화면 증가 $0.15(센트 반올림, $0.145~$0.155 범위) 안에 든다. 화면이 센트 단위라 이보다 정밀한 비교는 할 수 없다.
- 요청·토큰: OpenAI 쪽이 요청 3건, 입력 토큰 3,872 더 많다. 요청 1건당 약 1,291토큰으로 자연어 명령 한 건(입력 약 1,290)과 같은 크기라, 묶음 밖의 자연어 명령 3건이 같은 기간에 들어간 것으로 보인다(어느 호출인지는 확인하지 못했다). 이 3건을 빼면 입력 토큰은 788,239로 DB와 맞는다. 후보: 묶음 직전(18:0x UTC)에 돌린 로컬 실제 확인 1차의 자연어 명령 3건 입력이 1,290·1,292·1,290 = 3,872로 정확히 같다. 사용량 화면이 수 분 늦게 반영돼 시작 전 값에 아직 들어가지 않았을 가능성이 크다(확인 1차의 진단 1건은 시작 전 값에 들어가 있었는지 확인할 수 없다).
- 한계: 시작 전 화면은 "최근 7일"(10/18~24), 후 화면은 "이번 주"(10/19~25)라 기간이 하루 다르다. 10/18 사용량은 0이라 영향이 없다. 출력 토큰은 화면에서 확인하지 못했다. 대조는 1회, `gpt-6-luna` 한 모델이다.
- 원자료 `.local/evidence/0176-llm-budget/reconcile*.{py,json,log,txt}`.
