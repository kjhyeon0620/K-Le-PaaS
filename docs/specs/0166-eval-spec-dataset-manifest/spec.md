# 진단 평가 명세·판정 가이드와 데이터셋 manifest

## 목적 / 성공 조건
- 목적: 지금 진단 평가는 "무엇을 정답으로 인정하는가"가 사례 파일과 스펙 여러 곳에 흩어져 있고, 정답 근거는 "하나라도 인용하면 통과"이며, 사례가 어떤 분할(개발·평가·강건성)에 속하는지 기록이 없다. 정답 기준을 한 문서로 고정하고, 사례마다 갈래·분할·근거 묶음·감사 상태를 붙여, 다음 이슈의 **동결 평가 세트**가 같은 기준과 형식으로 들어올 수 있게 한다.
- 기술적 완료:
  - `docs/eval/diagnosis-eval-spec.md`: 평가 단위, 갈래 5개, 라벨 6개별 판정 가이드(입증 증거·보조 조건·반례·라벨 깊이), 최소 충분 근거 묶음, 허용 가설·금지 단정, 지표 정의(원시/보정 분리, 사례 단위 통계).
  - 사례 형식 확장(기존 필드 유지): `episode_id`, `slice`, `split`, `injection{intent, observed, recovered}`, `expected.evidence_sets`, `expected.allowed_hypotheses`, `expected.forbidden_assertions`, `audit{status, reason, at}`.
  - 기존 75사례(#99 12, #123 평가용 39, #158 24)에 위 필드를 채운다. #123 조정용·과거 사건 35개는 RAG 조정 자료로 두고 평가 분할에 넣지 않는다.
  - `backend/src/test/resources/diagnosis-eval/manifest.json`(데이터셋 버전, 분할별 사례 목록과 SHA-256, 갈래 분포), `CHANGELOG.md`, `DATASET_CARD.md`.
  - 테스트: 사례 형식, manifest 해시 일치, `evidence_sets`의 모든 위치가 입력에 존재, `test` 분할의 에피소드가 다른 분할에 나타나지 않음, `test` 분할 파일이 바뀌면 실패.
  - 하네스: 원시 출력 기준 **근거 충분율**(최소 충분 묶음 하나를 완전히 인용)과 무관 인용 수를 표에 추가. 기존 "근거 일치"는 이름을 유지하고 정의를 표에 명시.

| 필드 | 값 | 기본값 |
|---|---|---|
| `episode_id` | 같은 장애의 시점·변형을 묶는 ID (#158 변형은 원본 ID) | 사례 `id` |
| `slice` | `SUPPORTED` / `UNSUPPORTED_OBSERVED` / `INSUFFICIENT` / `CONFLICT` / `ROBUSTNESS` | 없음 (필수) |

| `injection` | `intent`(의도한 결함), `observed`(관측으로 입증된 결론), `recovered`(주입 해제 후 회복 확인 여부, 모르면 `null`) | 캡처가 아니면 생략 |

| `audit` | `status`(`kept`/`corrected`/`multi_answer`/`undecidable`), `reason`, `at` | 기존 문자열 `audit`은 `reason`으로 옮김 |

- 분할 배정(측정 전 고정): #99 12·#123 평가용 39 → `dev`(규칙·프롬프트를 고치며 본 사례). #158 24 → `robustness`(감사용 1은 `slice=CONFLICT`, `audit.status=undecidable`로 자동 채점 제외). `test`는 비어 있다(다음 이슈).

- `evidence_sets`는 판정 가이드의 입증 증거로 정한다. 저장된 모델 응답의 인용을 보고 정하지 않는다.

- 확인할 것: 로컬 Docker k3s(ARM64)가 amd64 이미지를 에뮬레이션으로 실행해 버리는지. 실행되면 아키텍처 불일치가 재현되지 않으므로 다른 방법(에뮬레이션 없는 노드, 또는 해당 쌍 제외)을 그 스펙에서 정한다.

- 없음 (테스트·문서만 변경).

## 회고
- 어긋난 점: 스펙의 "같은 에피소드가 두 분할에 걸치지 않음"은 `dev` 원본과 `robustness` 변형 관계를 고려하지 않았다. 감사용 사례의 분할도 생성기 구조와 맞지 않았다. 둘 다 구현 중 결정으로 고쳤다.
- 어긋난 점: "무관 인용"이라는 이름은 맥락 인용까지 오류처럼 보이게 했다. 결과를 보고 이름만 바꿨다.
- 원인 분류: 스펙 누락 (변형 사례의 에피소드 관계를 분할 규칙에 반영하지 않음).
- 고친 위치: 이 스펙 결정 기록, `docs/eval/diagnosis-eval-spec.md` §7.
- 남은 것: `test` 분할 채우기·정답 일치도·동결 측정은 다음 이슈다. `dev` 근거 묶음은 사람 재검토를 받지 않았다.
