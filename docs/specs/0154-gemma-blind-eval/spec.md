# test: 독립 작성 평가 세트로 로컬 gemma4 진단 검증

## 목적 / 성공 조건
- 목적: #152에서 로컬 `gemma4:26b-a4b`(생각 끔)가 #99 진단 12사례로 `gpt-6-luna`와 같은 수준이었다. 그 세트는 포화에 가까워(로그에 원인이 드러난 사례 위주, 12개) 결론을 일반화하기 어렵다. #123에서 다른 모델이 목적을 모른 채 만들고 로컬 k3s에서 재현한 평가용 39사례로 같은 결론이 나오는지 확인한다.
- 기술적 완료: 평가용 세트를 RAG 없음 × 3회로 한 번만 측정하고, #123의 `gpt-6-luna` RAG 없음 결과와 같은 지표로 비교한다.
- 운영: 기본값·운영 설정은 바꾸지 않는다. 결과가 기준에 못 미치면 "독립 평가에서는 대체 후보가 아님"이 결론이다.

## 실행 결과

### 평가용 39사례 × 3회 (2026-10-21 20:45~21:23, 한 번만 측정)
- 로컬 + Ollama(위 측정 조건, 컨텍스트 32K). 호출별 입력 토큰 최대 4,491. 오류 0.
- `gpt-6-luna` 행은 #123 RAG 없음(2026-10-11, 동시 호출 4)을 옮겼다. 신뢰구간은 #123과 같이 호출 117개 기준 Wilson 95%.

| 모델 | 구체 원인 (95% CI) | 범주 | 판단 보류 | 잘못된 단정 | 근거 유효 | 사례 다수결 | 공개 이미지 (25) | 사내 서비스 (14) | 지연 중앙·p90 ms | 판정 |
|---|---|---|---|---|---|---|---|---|---|---|
| `gpt-6-luna` (#123) | 116/117 (99%, 95–100%) | 116/117 | 1/117 | 0/117 | - | 39/39 | - | - | 4,522 · - | 기준 |
| `gemma4:26b-a4b` | **117/117 (100%, 97–100%)** | 117/117 | 0/117 | 0/117 | 117/117 | 39/39 | 75/75 | 42/42 | 19,346 · 26,142 | **통과** |

- 판단 보류 0: 평가용 사례는 모두 원인을 단정해야 하는 사례라 보류하지 않은 것이 정답이다(판단 보류 항목 117/117 = 보류 판단이 기대와 일치).
- `g1-mq-prb-proto`(라벨은 probe_protocol_mismatch, 관측은 mosquitto 로컬 전용 모드로 인한 connection refused, #123 기록): 3회 모두 라벨과 같은 probe_protocol_mismatch로 답했다. 요약에서 "HTTP probe로 MQTT 1883 포트에 접근"을 근거로 들어, 관측(포트 닫힘)보다 설정 차이를 원인으로 봤다. #123 원칙대로 라벨로 채점했다.
- 지연은 판정에 넣지 않았다. 평가용 사례는 #99보다 입력이 길어(#152 진단 중앙 11,649ms) 더 걸렸고, 측정 중 같은 장비에서 다른 GPU 작업이 있어 참고값이다.

### 결론
- **`gemma4:26b-a4b`(생각 끔)는 독립 작성 평가용 세트에서도 `gpt-6-luna`와 구별되지 않는다.** 구체 원인 117/117, 잘못된 단정 0, 근거 유효 117/117, 공개 이미지·사내 서비스 모두 만점이다. #152(#99 세트)의 결론이 다른 모델이 만든 39사례에서도 유지됐다.
- 두 모델 모두 이 세트에서 거의 만점이라, 이 세트도 두 모델의 차이를 가려내기에는 쉽다. "gemma가 더 정확하다"가 아니라 "외부 전송 없이 같은 수준의 진단을 낼 수 있다"로 쓴다. 실제 운영 장애 사례로의 일반화는 검증하지 않았다.
- 지연은 운영 모델의 약 4배라, 대화형보다는 실패 직후 백그라운드 진단에 맞다.
- 운영 기본값은 바꾸지 않는다(운영 서버에 GPU 없음).
