# 저장된 자연어 명령 응답 재채점으로 평가 회귀 게이트

## 목적 / 성공 조건
- 목적: 자연어 명령 평가(#58, 30사례)는 지금 손으로 재채점 모드(`NLP_EVAL_REPLAY`)를 돌려야 결과를 확인할 수 있다. 저장된 원문은 `.local/`(git 제외)에만 있어서 CI가 볼 수 없다. 그래서 응답 파서(`IntentParser`), 위험도 분류(`ActionDispatcher.classifyRisk`), 변경 intent 목록, 채점기(`NlpEval`), 정답(`cases.json`)을 바꾸는 PR이 기존 평가 결과를 바꿔도 드러나지 않는다. 특히 **상태를 바꾸는 명령이 승인 없이 실행될 해석(`unconfirmed_change`)** 이 새로 생겨도 PR에서 보이지 않는다. #172(진단)와 같은 구조로, 기준 실행의 모델 원문을 저장소에 두고 매 PR마다 모델 호출 없이 다시 채점해 결과가 바뀌면 실패하게 한다.
- 기술적 완료:
  - 기준 실행 원문(모델 응답 텍스트만. 사례 입력은 이미 저장소에 있다)을 `backend/src/test/resources/nlp-eval/baselines/`에 둔다.
  - 회귀 테스트가 기준마다 지금 코드로 다시 채점해 저장된 기대 요약과 같은지 본다. 다르면 차이 표를 출력하고 실패한다. 채점하는 것은 항목별 판정(파싱·intent·인자·날조·변경 intent 날조·과소·과대·확인 없이 변경), 원시 출력 계약(#159), 반복 일관성(pass^1·pass^n, #156), 사례별 호출 판정이다.
  - 기대 요약을 바꾸려면 쓰기 모드로 다시 만들고, 변경 이유를 사례 파일 옆 CHANGELOG에 적는다. 차이는 PR diff에 그대로 보인다.
  - 회귀 표를 기존 진단 회귀 표와 함께 CI 작업 요약에 붙인다.
- 운영: 변경 없음(테스트와 CI만 바뀐다).

## 입출력·계약
- 기준 파일(모델별 JSON): `{baseline_id, model, system_prompt_sha256, cases_version, measured_at, source(스펙 번호), runs: {case_id: [raw, ...]}}`. 사용량과 지연은 넣지 않는다.
- 기대 요약(`baselines/expected.json`): 기준마다 다음을 담는다.
  - 호출 수와 호출 오류 수
  - 항목별 판정 합계(`NlpEval.ITEMS`), 원시 계약 합계(`NlpEval.RAW_ITEMS`), pass^1·pass^n, 갈래별(정상·모호·위험) 반복 모두 통과 수
  - 사례별 호출 판정 문자열. 기호는 구현 때 정한다. 예: P 통과, X 파싱 실패, I intent 오답, A 인자 오답, F 날조, U 확인 없이 변경
- 프롬프트 불일치: 기준의 `system_prompt_sha256`이 지금 `prompts/system-prompt.txt`의 SHA-256과 다르면 실패하고 "새 기준 실행이 필요"라고 알린다(Q2).
- 쓰기 모드: `NLP_BASELINE_WRITE=1`일 때만 기대 요약을 다시 쓴다.
