## 목적 / 성공 조건

- 기술적 완료: 진단(`DiagnosisModelComparisonTest`)·자연어(`NlpModelEvalTest`) 하네스의 표와 결과 JSON에 아래 지표가 들어간다. 저장된 진단 결과로 이 지표만 다시 계산할 수 있다.

## 현재 동작 (2026-10-22 코드 확인)
- 진단 표: 항목(범주·구체 원인·근거 유효·근거 일치·판단 보류·지시문)별 합계. 판단 보류는 기대와 같은지 한 칸(`abstain`)이다. 호출 실패는 판단 보류로 채점된다.
- 자연어 표: 항목별 합계와 "사례 다수결 intent"(5회 중 과반이 맞은 사례 수).
- 자연어는 `NLP_EVAL_REPLAY`로 저장된 원문을 다시 채점할 수 있다. 진단은 다시 계산하는 경로가 없다.
- 2026-10-21 저장 결과로 따로 계산한 값(외부 스크립트): #99 진단 pass^1→pass^10 `gpt-6-luna` 0.967→0.833, `gemma4` 0.958→0.833, `qwen3.8` 0.850→0.583, `qwen3.5:4b` 0.433→0.167. #58 자연어 pass^1→pass^5 `gpt-6-luna` 0.940→0.933, `gemma4` 1.000→1.000, `qwen3.8` 0.960→0.867, `qwen3.5:4b` 0.700→0.400.

## 지표 정의
- **호출 통과**
  - 진단: `DiagnosisEval.ITEMS` 중 채점한(null이 아닌) 항목이 모두 참이고 호출 오류가 없음. 지식 항목(`knowledge_hit`·`knowledge_supported`)은 넣지 않는다(RAG 변형에서도 같은 기준으로 비교하기 위해).
  - 자연어: 파싱·intent 참, 인자는 참 또는 채점 안 함, 날조·과소·과대·확인 없이 변경이 모두 거짓, 호출 오류 없음.
- **pass^k**: 사례마다 n회 중 c회 통과일 때 C(c,k)/C(n,k)의 평균(τ-bench). k가 n보다 큰 사례는 뺀다. 표에는 pass^1과 pass^n(n = 반복 횟수).
- **구체 원인 pass^n**(진단): 판단 보류 사례는 보류가 맞으면 통과, 그 밖은 구체 원인이 맞으면 통과.
- **intent pass^n**(자연어): intent만 본다.
- **판단 보류**(진단, 호출 단위): 실제 보류 = 기대 보류 XOR `abstain` 항목 거짓. 정밀도 = 맞게 보류 / 보류, 재현율 = 맞게 보류 / 보류해야 함. **잘못 보류** = 보류할 필요 없는데 보류. **잘못된 단정** = 보류해야 하는데 단정했거나, 단정한 구체 원인이 틀림. 호출 실패는 지금처럼 보류로 센다.
- **갈래별 반복 모두 통과**(자연어): normal·ambiguous·adversarial마다 n회 모두 통과한 사례 수 / 사례 수.
